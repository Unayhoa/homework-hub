# 考试数据采集审计（2026-11-01）

按「app 的核心定位是聚合跨平台的作业与考试」这条第一原则，逐平台核对**考试**到底从哪来、
现在实现走的是哪条路、有没有 HAR 证据。所有结论都来自用户提供的真实 HAR，
不采信社区代码或历史注释。

## 一、结论总表

| 平台 | 考试的真实数据源 | 当前实现 | HAR 证据 | 判定 |
|---|---|---|---|---|
| 超星学习通 | `GET /exam-ans/mooc2/exam/exam-list`，时间在 `onclick="goTest(...)"` 第 4 参 | 同左（2026-11-01 重写） | ✅ 有 | **正常** |
| 长江雨课堂 | 章节树里**没有**考试（leaf_type 只有 7/8/9）；`/api/v3/classroom/on-lesson-upcoming-exam` 的 `type` 字段才是分类依据 | 章节树取作业；upcomingExam 只用来拼作业链接 | ⚠️ 有，但样本课程无考试 | **考试从未被采集**（已补：采 `type==='exam'`） |
| PTA 拼题A | `GET /api/problem-sets/{id}/exams` → 考试实例（`startAt`/`endAt`/`status`/`ended`） | 只用 `/api/problem-sets` 列表，`kind` 恒为 `homework` | ✅ 有 | **考试被当成作业**采集（时间能拿到，类型丢失） |
| iSmart | `POST /client/homework/v2/list-of-student?testStatus=&courseId=`，字段 `test_type` | `POST /client/homework/tests/list-of-student`，`test_type===2 → quiz` | ⚠️ 有，只有 `test_type:2` 一条 | **类型映射不完整**，`exam` 对应哪个取值未知 |

## 二、逐平台细节

### 超星（已修）

```
GET mooc1.chaoxing.com/exam-ans/mooc2/exam/exam-list
    ?courseid=&clazzid=&cpi=&ut=s&t=&stuenc=
```

每条 `<li>`：

```html
<div onclick="goTest('204587864',11006129,0,'2026-11-02 11:40:00.0',…,'enc','0');">
  <p class="overHidden2 fl">期中考试</p>
  <p class="status fl">未开始</p>
```

- 时间在 `goTest` 第 4 个参数，**页面上不显示**——这是"截止未知"的真正原因
- examId 在第 2 个参数
- 参数名全小写 `courseid`/`clazzid`（作业接口是驼峰）

走过的两条死路（写在代码里防复发）：
1. `mooc-ans/exam/test/getAllExam` —— 404
2. `mooc-ans/exam/phone/task-list` —— 200 但**空壳**（只有隐藏 input，列表 JS 再拉）

### 雨课堂（本次补采集）

章节树 `mooc-api/v1/lms/learn/course/chapter` 的 `leaf_type` 实测只有三种：

| leaf_type | 数量 | 样例 | 含义 |
|---|---|---|---|
| 7 | 1 | 第三章第3节-原版 | 资料 |
| 8 | 13 | 9月9日授课 | 课堂活动 |
| 9 | 8 | 信安第一次作业(1) | 作业/测验 |

**没有考试**。而 `on-lesson-upcoming-exam` 返回：

```json
{"data":{"upcomingExam":[{
  "classroom_name":"2026秋-25网络空间01…",
  "title":"信安第八次作业(1)",
  "type":"quiz",
  "start_time":1792546896,   // epoch 秒
  "end_time":1793203140,
  "classroom_id":26617021,
  "id":1761098
}]}}
```

- `type` 是字符串，样本里只有 `"quiz"`
- 这段以前**只取 id 拼作业链接，条目本身被丢弃** → 若存在 `type:"exam"` 的条目，永远不会进库

已改：`type === 'exam'` 的条目单独采集成 `kind:'exam'`；
并把见过的 `type` 取值写进同步日志（一次同步就能看出考试在这个接口里叫什么）。

**未验证的部分**：样本课程没有考试，所以 `"exam"` 这个取值本身没有实证。
如果日志里出现的 type 不是 `exam`（比如 `homework` / `test`），按实际值再改一次即可。

### PTA（结论：考试被当作业，未改）

同一份 HAR 里，题目集列表与考试实例是两个接口：

```
GET /api/problem-sets/{id}          → 403（需要权限）
GET /api/problem-sets/{id}/exams    → 200，考试实例
GET /api/exams/{examId}/problem-sets/{id}/problem-status
```

`/exams` 返回：

```json
{"exam":{"id":"2110298075464994816","score":100,
         "startAt":"2026-10-14T09:14:03Z","endAt":"2026-10-22T15:50:00Z",
         "ended":false,"status":"PROCESSING"},
 "problemSet":{"id":"2109129330082820096","name":"25级数据结构上机实验…",
               "type":"EXERCISE","timeType":"FIXED_TIME"}}
```

现状：适配器只读 `/api/problem-sets` 列表，`kind` 恒为 `homework`。
所以**考试的时间能采到**（问题集自己带 endAt），但类型不区分、也拿不到考试状态。

改动成本：要对每个题目集多打一次 `/exams`（N 个请求），且 `timeType` 并不能等价于"考试"
（样本里 `type:EXERCISE` + `timeType:FIXED_TIME` 是"限时上机实验"，不是考试）。
**需要用户确认一件事**：PTA 上的「考试」在页面上和「限时练习」怎么区分？
在拿到这个答案前不动 `kind` —— 猜错的代价是提醒策略和分组一起错。

### iSmart（结论：待补样本）

```
POST /client/homework/tests/list-of-student        （适配器在用）
POST /client/homework/v2/list-of-student?testStatus=0&courseId=  （HAR 里也有）
```

字段：`test_type`、`testStatus`、`begin_time`/`end_time`（epoch 毫秒）、`test_id`、`test_name`。

适配器：`test_type === 2 ? 'quiz' : 'homework'`。
HAR 里只有一条 `test_type:2`（是一条填空测验）。**`exam` 对应哪个取值没有证据**。

边界：iSmart 的 `capabilities.exams: false`，声明是诚实的（确实没做），
但与"这个平台没有考试"不是一回事 —— 平台有，只是没采。

## 三、结构性教训

1. **`capabilities.exams` 没有任何消费方**（全项目只有赋值，没有读取）。
   所以它常年撒谎也不会有人发现：超星写 `true` 而接口 404、PTA 写 `true` 而 `kind` 恒为 homework。
   已定规则：不写没有读者的声明。
2. **"能同步到作业"给了虚假的安全感**。作业路径跑通后，没有任何机制会去碰考试那条分支；
   而考试失败只 `errors.push`，`items` 非空时不报 → 完全静默。
   已定规则：某一类数据整体失败，必须走 `Page.notes`（弹窗）或 `Page.details`（日志）。
3. **社区代码不等于已验证**。超星的 `getAllExam` 是继承来的，注释挂着 `TODO(verify)` 就上线了。
   已定规则：任何平台接口，要么有 HAR 证据，要么标 `TODO(verify)` 并在诊断里体现"未验证"。

## 四、下一步（按收益排序）

1. **PTA 考试区分**：需要用户回答「考试 vs 限时练习在界面上怎么区分」。
2. **雨课堂 type 取值**：下次同步日志里会打印；若出现 `exam` 以外的值，按实际改。
3. **iSmart `test_type`**：需要一份**含考试**的 iSmart HAR（课程里有"考试"入口）。
4. 三个平台的考试都补齐后，再把 `capabilities.exams` 接上消费方
   （界面标注"该平台不采集考试"），否则它还是纸面承诺。
