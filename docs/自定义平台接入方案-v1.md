# 自定义平台接入方案 v1

> 面向 homework-hub（当前 v0.2.8）。
> 范围只有一件事：**让「添加一个没见过的平台」这件事，对用户来说接近零成本，且结果可信。**
> 不涉及内置四个平台的适配器重写，不涉及提醒策略改动。

---

## 0. 历史决策（为什么是现在这个样子）

| 版本 | 发生了什么 | 留下的约束 |
|---|---|---|
| v0.2.4 | 自定义平台两条路：API（声明式配置）/ DOM（点选） | 两条路实现同一个 `PlatformAdapter`，上层零改动 |
| v0.2.6 | 「待办有作业、课程页说没有课程」| 课程维度被 `capabilities.courses=false` 写死关掉了 |
| v0.2.7 | 采集数据不再只分享给外部 AI，改为回传应用内；识别由服务端完成 | AI 降级为失败时才出现的兜底 |
| v0.2.8 | 一门课被拆成 4 门（含一门叫 `11430986`）| 结构识别分不清「课程目录」与「课程内容」，必须引入地址里的 courseId 做锚点 |

从这几轮里压出来的**四条不可推翻的原则**：

1. **判据挂在真正的变量上。** 不是"能不能加平台"，而是"加完之后能不能一直正确同步"。
2. **结构特征负责发现，确定事实负责定界。** 启发式只用于排序，不用于断言语义（课程归属必须由 URL / 课程表这类确定信息决定）。
3. **AI 的能力边界写进代码，不写进提示词。** 修不了的事（会话、签名、网络）一个字节都不发给 AI。
4. **用户只做不可替代的动作。** 凡是他"照着说明操作"的步骤，都说明有一件本该由代码判断的事被推给了他。

## 1. 目标与边界

### 1.1 目标（可度量，不是口号）

| 指标 | 现状 | 目标 |
|---|---|---|
| 首次接入一次成功率（真机：新平台→待办出现正确作业） | 未验证 | ≥ 70%（无 AI 介入） |
| 启用后 7 天内仍正确同步的平台占比 | 未验证 | ≥ 90% |
| 用户动作数（成功路径） | 2 次点击 + 登录 | 不增加 |
| 失败路径用户动作数 | 复制 + 粘贴 2 次 | ≤ 4 次，且不需要理解任何字段名 |
| 课程归属错误率 | 曾出现 1 门拆 4 门 | 0（靠锚点/课程表，不靠猜） |

### 1.2 明确不做

- **不做写入**。任何"帮用户提交/签到/改状态"都不做，只读是第一天起的安全边界。
- **不做通用爬虫引擎**。不执行 JS、不支持需要签名的接口（enc/sign 由页面现算，原理上做不稳）。
- **不追求 100% 平台覆盖**。覆盖不了的平台要**当场说清楚 + 给出可走的路**（DOM 点选 / 手动作业），而不是给一个"看起来接上了"的假成功。
- **不为了少一次点击牺牲正确性**。比如不为了"全自动"而允许未经试抓就启用。

## 2. 用户动作与成本预算

### 2.1 成功路径（目标态）

| # | 动作 | 谁做 | 成本 | 备注 |
|---|---|---|---|---|
| 1 | 填网址，点「下一步」 | 用户 | 1 次输入 + 1 点击 | 平台名可留空 |
| 2 | 在平台页登录，点进作业列表 | 用户 | 不可替代 | 只有他有账号、只有他知道哪页是列表 |
| 3 | 点「我看到了作业 · 回应用」 | 用户 | 1 点击 | 之后无输入 |
| 4 | 看到「能读出来了 · N 条」，点「启用」 | 用户 | 1 点击 | 若只有 1 个候选通过，可默认选中 |
| 5 | （自动）同步，待办出现作业 | 代码 | 0 | 不需要他再点同步 |

**预算：2 次点击 + 1 次输入 + 登录。失败路径只允许再加「复制一次 + 粘贴一次」。**

### 2.2 失败路径的分流（关键）

失败不是"给一个错误"，而是**给一条最短的可走路**：

| 失败类型 | 用户看到的 | 用户要做的 |
|---|---|---|
| 没认出接口 | 一句话 + 「再翻一次作业列表」或「复制给 AI」 | 优先重试，其次复制 |
| 接口对、解析空 | 「复制给 AI」（含当前配置 + 结构摘要） | 复制 → 粘回 |
| 会话失效 | 「去重新登录」 | 打开页面登录，无 AI |
| 签名参数 | 「改用页面点选」 | 点选一次，无 AI |
| 网络/超时 | 「重试一次」 | 点一下，无 AI |

## 3. 架构：四层，各自只回答一个问题

```
采集层  Capture   「这个平台的数据长什么样？」   → 样本集（含上下文）
识别层  Analyze   「哪份是作业、每列是什么？」   → 候选配置（带证据与不确定度）
验证层  Verify    「这份配置真的能用吗？」       → 试抓结果 + 二次同步校验
修复层  Repair    「失败了谁修、给什么材料？」   → 错误码 → 动作 or AI 包
```

层间只传**结构化对象**，不传文案。文案只在最后一层（Repair / UI）生成。
这条边界的意义：**识别和验证永远不需要知道"用户会怎么被提示"**，提示词改动不会影响判定逻辑。

### 3.1 采集层：从「单点快照」升级为「会话样本集」

**现状缺口**：只记录用户点回应用那一刻内存里的请求。懒加载、无限滚动、翻页、需要点进详情才出现截止时间的平台，全部漏。

设计：

- 样本集 = `{ context: {origin, pageUrl, pageTitle, capturedAt}, requests: [...], actions: [...] }`
- `actions` 记录**用户行为标记**：进入作业列表、翻页、滚动到底、点开详情。
  这是识别层的"哪段数据更可能是作业"的强信号，比 URL 猜更准。
- 采集持续进行（不只一次 dump）：用户每次点「回应用」都把**新增**样本追加进同一份会话样本集。
  于是"再翻一页再回来"是**增量补充**，而不是从零重来。
- 录制器补两个低成本能力：
  - 滚动/翻页时自动打标（`__hhMark('page:N')`），不需要用户额外操作；
  - 记录**发生顺序**，识别时"作业列表接口"通常在用户进入列表页之后才出现，给时间靠后的样本加权。
- **样本落盘为脱敏样本包**（见 §6），这是后续所有回归的弹药。

### 3.2 识别层：候选排序 + 语义定界

沿用并强化现有 `probe.ts`，但把职责分清：

| 子任务 | 靠什么 | 不允许靠什么 |
|---|---|---|
| 找出数组 | 结构遍历 | — |
| 判断"像不像作业列表" | 标题列 + 时间列/状态列 + URL 路径分段 | 不能只看字段名 |
| 判定"这是不是课程目录" | **课程表接口 / 地址 courseId / 页面层级** | **禁止**仅凭 `id+name` 结构认定 |
| 字段映射 | 后缀匹配 + 取值统计（唯一性/重复度/时间可解析率） | 不能要求字段精确叫 `name` |
| 状态语义 | 取值集合 + 用户可见文案 | 不能只靠"有 status 字段" |
| 分页 | URL 参数 + total/hasMore 字段 | 不能默认"一页就是全部" |

**三条新的硬规则：**

1. **凡能由确定信息决定的，绝不用启发式。**
   课程归属优先级：显式课程 ID > 课程表按名匹配 > URL 锚点 > 任务行字段（且该字段必须通过"像课程名"校验）> 兜底单课程。
2. **识别结果必须带"不知道"的选项。**
   每个字段允许 `null` + `reason`，而不是硬塞一个最像的。比如状态字段判不出是否表示完成，就写 `usableForCompletion: false`，让任务走 `inferred`（用户可手动标），而不是假装平台说"未完成"。
3. **课程内容与课程目录必须分开判分。**
   含文件名/时长/大小/章节序号特征的数组，直接排除出课程目录候选。

### 3.3 验证层：三级，逐级变贵

| 级别 | 做什么 | 成本 | 拦截什么 |
|---|---|---|---|
| L1 结构校验 | 配置是否完整、路径能否命中样本 | 0 请求 | 字段写错、listPath 错 |
| L2 试抓 | 真发一次请求，用**同一个适配器**解析 | 1 请求 | 接口地址错、会话失效、签名 |
| L3 启用后首同步校验 | 启用后第一次同步，核对"非空 + 字段非空 + 课程非异常" | 已有同步 | "试抓过了但同步是空的" |

**L3 是现在没有的，也是最该补的**：试抓只证明"那一刻能读"，不证明"这条链路稳定"。
首同步若出现 0 条/课程数异常/全部无标题，必须**显式报出来并给出修复入口**，不能静默。

### 3.4 修复层：错误码先行，提示词按码分发

**现状缺口**：`classifyFailure` 靠正则匹配错误文案。文案一改，分类就漂移，而且漂移时没有任何提示。

设计：

- 适配器抛错必须带**结构化 `code`**（`AUTH_REQUIRED / UPSTREAM / PARSE_EMPTY / SELECTOR_STALE / SIGNATURE_REQUIRED / NETWORK / RATE_LIMITED / UNKNOWN`），`message` 只用于展示。
- `diagnostics` 只按 `code` 分发，不再读 message。读不到 code 的归 `UNKNOWN`，走保守路径。
- 每个 code 绑定四件事：**一句话 / 一个主动作 / 是否需要 AI / 给 AI 的材料与提示词**。

| code | 用户动作 | 给 AI？ | 提示词目标 |
|---|---|---|---|
| `AUTH_REQUIRED` | 去重新登录 | 否 | — |
| `SIGNATURE_REQUIRED` | 改用页面点选 | 否 | — |
| `NETWORK` / `RATE_LIMITED` | 稍后重试 | 否 | — |
| `PROBE_EMPTY` | 重新采集 or 复制给 AI | 是 | 从结构摘要里挑出作业接口 |
| `PARSE_EMPTY` | 复制给 AI | 是 | 只修 listPath / fields 路径 |
| `SELECTOR_STALE` | 重新点选 or 复制给 AI | 是 | 只修 DOM 选择器 |
| `COURSE_MISMATCH` | 复制给 AI（或重采到课程目录页） | 是（低优先） | 判定哪个是课程表、哪个是课程内容 |
| `UNKNOWN` | 复制给 AI（全量诊断包） | 是 | 只读材料、给出最可能的一处 |

## 4. 提示词设计（针对免费模型的真实能力）

免费模型的失败模式已经实测过：**爱提取数据、不按格式、答非所问、看不完长文、会给"听起来合理"的错答案**。
所以提示词必须按"它最容易做对的那种任务"来设计，而不是按"我们希望它做什么"来设计。

### 4.1 六条硬约束

1. **一个提示词只让它做一件事。** 挑接口 / 修路径 / 修选择器，绝不混在一份里。
2. **材料里绝不出现作业正文与个人信息。** 值一律换成 `<string len=N>`，只留结构、字段名、URL、时间样例。
   （原因已实测：只要看得见标题，它就会去"提取作业"。）
3. **只输出 JSON，且输出 schema 必须短。** 超过 8 个字段的 schema 免费模型很容易漏。
4. **允许它说不知道。** 提供 `{"need_more":[...], "confidence":0.x}` 出口，否则它会编。
5. **要求它"只改错处"，并给出当前完整配置。** 重写会把已经对的部分也改掉（真机踩过：courseId 被写成页码）。
6. **提示词与材料合一。** 用户只复制一段，不需要记得"还要再发提示词"。

### 4.2 提示词清单（每份都要有验收断言）

| 名称 | 用途 | 输入材料 | 输出 | 验收断言 |
|---|---|---|---|---|
| `PICK_ENDPOINT` | 从多个接口里挑作业列表 | 各接口的结构摘要 + URL | `{url, listPath, fields, confidence}` | url 必须出现在材料里；fields.title 非空 |
| `FIX_PATHS` | 修 listPath / fields | 错误原文 + 当前配置 + 响应结构 | 完整配置 | 除 listPath/fields 外与原配置逐键一致 |
| `FIX_DOM` | 修选择器 | 错误原文 + 当前 DOM 配置 | 完整 DOM 配置 | mode 仍为 dom；只动 readyWhen/rows/fields |
| `CLASSIFY_COURSE` | 区分课程表与课程内容 | 两个数组的结构 + 页面地址 | `{kind: "course-list"|"course-content", reason}` | 只能二选一，必须给理由 |
| `MAP_STATUS` | 把平台状态值映射成完成/未完成 | 状态字段的全部取值 + 样例 | `{values: {...}, usableForCompletion: bool}` | 取值必须全部来自材料，不许新增 |

**提示词要有版本号**（如 `PICK_ENDPOINT@v3`），并配一组"材料 → 期望输出"的样例。
改提示词时跑样例：不是测 AI 准不准（那不可控），而是测**我们的解析器能不能接住它典型的输出形态**
（带解释文字、```json 包裹、字段缺失、裸引号、中文引号）。

## 5. 关键缺口与对应解法（本方案真正要新增的东西）

| # | 缺口 | 解法 | 优先级 |
|---|---|---|---|
| G1 | 完整链路未真机验证 | 先做 P0 验证清单，不扩功能 | P0 |
| G2 | 单课程锚点＝只能读一门课 | 支持「课程目录页 → 逐课程任务接口」的两段式配置；无课程表时才退回锚点 | P2 |
| G3 | 懒加载/翻页漏数据 | 会话样本集 + 行为标记 + 增量回传 | P1 |
| G4 | 试抓过但同步空 | L3 首同步校验 + 明确报错 | P1 |
| G5 | 错误分类靠文案正则 | 全链路错误码化 | P1 |
| G6 | 状态只认中文 | `MAP_STATUS` 提示词 + 取值白名单校验；认不出就 `inferred`，不假装 | P1 |
| G7 | 没有回归弹药 | 脱敏样本包沉淀为测试库，识别器改动必须跑全库 | P2 |
| G8 | 提示词改动无保障 | 提示词版本 + 输出形态样例测试 | P2 |
| G9 | 脱敏只覆盖 URL | 样本入库前剔除身份类响应（user/info、profile、手机号/学号字段） | P1 |

**G2 的取舍要说清**：多课程是结构成本最高的一项。
如果某个平台**没有**干净的课程表接口，两段式配置就退化成"每门课一份锚点配置"，
此时**不要**强行自动展开成多课程——那会把 G2 变成下一个"一门拆四门"。
先保证"这一门一定对"，再谈"多门也能对"。

## 6. 样本库：让识别器可以离线变聪明

每次采集结束，把样本**脱敏后**存为一个可重放样本包：

```json
{
  "schema": 1,
  "platformHint": "wenda.zhihuishu.com",
  "capturedAt": "…",
  "context": { "pageUrl": "…(脱敏)", "pageTitle": "…" },
  "requests": [ { "url": "…(脱敏)", "status": 200, "body": "…(结构脱敏，保留时间样例)" } ],
  "expect": { "taskCount": 2, "courseCount": 1, "courseName": "舞蹈欣赏" }
}
```

- `expect` 由**用户确认识别结果那一刻**回填（他说"对，就是这门课、这两条作业"）。
  这样每个成功/失败的案例都变成可回归的判据，而不是一次性现场。
- 隐私：样本包**默认不含作业标题正文**；`expect` 里的课程名属于结构事实，可保留。
  不愿意保留的可一键删除，样本库只是本地文件。
- 识别器/提示词每次改动，跑全样本库：输出 diff（哪个平台从对变错）。
  **没有样本库，任何"识别率提升"都是感觉。**

## 7. 分期与验收

### P0：把已有的跑通（不新增功能）
- 真机走通：智慧树 API 模式 + 一个 DOM 模式平台。
- 验收：待办出现正确作业；课程只有「舞蹈欣赏」；课程归属 0 错误；无全屏蒙版。
- 产出：真实样本包 ≥ 2 份 + 失败现场记录。

### P1：失败闭环与稳定性
- 错误码化（G5）、L3 首同步校验（G4）、会话样本集与增量回传（G3）、
  状态映射与脱敏增强（G6/G9）。
- 验收：每一类错误都有唯一出口；试抓过但同步空的情况必定显式报错；
  样本包可重放；单测覆盖新增分支。

### P2：覆盖面与可持续
- 两段式多课程（G2）、样本库驱动回归（G7）、提示词版本与样例（G8）。
- 验收：多课程平台能正确归属；识别器改动有全库 diff 报告；
  提示词改动不会让我们的解析器接不住。

## 8. 这套方案最容易被做坏的地方（写给执行者）

1. **把"识别率"当成可以调参调出来的东西。** 真正的提升来自"多一条确定信息"
   （URL、行为标记、课程表），不是把正则写得更复杂。
2. **为了让成功率好看而放宽校验。** 那等于把错误从"识别失败"挪到"启用后同步为空"，
   而后者难查得多。
3. **给 AI 的任务越写越大。** 一旦让它"顺便把课程也判了、状态也映射了"，
   输出就会开始缺字段、开始编。宁可多一次复制，也不要一个巨型提示词。
4. **前端开始自己拼文案/拼提示词。** 那样就有 N 个地方维护同一件事，质量随机且必然漂移。
5. **没有样本库就改识别器。** 每改一次都可能把某个已跑通的平台改坏，而且没人知道。
